# 产品决定与反思

## 已修正的问题

1. **演示数据不能伪装成真实岗位。** 示例只用于首次引导，真实扫描结果必须带官方来源和扫描状态。
2. **网页 localStorage 不适合桌面隐私数据。** 桌面版改为应用私有目录中的原子写入数据文件，并提供备份与恢复。
3. **不能给出无法解释的精确匹配分。** 当前使用等级、命中关键词和缺口证据，让用户知道结论从哪里来。
4. **不能直接改坏主简历。** JD 定制应产生建议或副本；主简历必须由用户明确保存。
5. **发现岗位不等于完成投递。** 系统分别记录发现、打开官网和用户确认已投递，统计只依赖用户确认。
6. **一个通用网页解析器无法覆盖全国企业。** 动态渲染、站点模板变化、登录和反爬都需要专用适配器与维护；失败必须被明确报告。
7. **应用关闭时无法自行按时运行。** 真正的每日两次后台扫描需要用户主动安装 Windows 定时任务，并应允许随时停用。
8. **GitHub 是源码仓库，不是个人数据仓库。** 真实简历、AI 密钥、历史记录和备份均被排除在版本控制之外。

## 明确边界

- 仅使用企业官方公开招聘入口或用户主动添加的官方来源。
- 不自动登录，不绕过验证码、短信、2FA、排队或访问控制。
- 不自动点击最终提交；最终投递由本人完成。
- 不自动回答薪资、身份、健康、政治面貌等敏感问题。
- 不编造候选人经历和成果。
- 只有用户确认后才把记录计入已投递数量。

## 首版验收标准

- Windows 或 macOS 本地启动，无需注册账号。
- 关闭并重新打开后，简历、岗位池和投递记录仍在。
- DOCX 可以导入，DOCX 可以真实导出，PDF 可通过系统打印保存。
- 至少一个静态测试招聘页可以完成抓取、筛选、去重和 JD 摘要。
- 来源不可访问或无法解析时，用户能看到失败原因。
- JD 建议同时显示命中证据和待核实缺口。
- 用户可一键打开官方岗位页，但最终提交必须在官网由本人完成。
- 备份和恢复可用，私密文件不会被 Git 跟踪。
- 自动化测试、类型检查和生产构建通过。
- Windows 可执行版本与 macOS Universal 版本能够启动，并记录包体、磁盘占用和运行内存。
