# 全国企业招聘入口方案

> 产品方向已调整为维护“城市—企业—官方招聘渠道”目录，不再复制和持续刷新全国岗位明细。以下岗位索引设计仅作为未来获得正式数据授权后的扩展方案。

## 目标

用户先输入省份、城市和目标岗位，软件从最近一次岗位快照中立即返回该城市的公司与岗位；点击刷新后只检查可能发生变化的来源，并标记新增、更新和疑似关闭岗位。

“全国覆盖”表示持续扩大可核验的官方来源，不表示互联网上所有岗位都能被完整、实时收录。

## 当前状态

- 预置 5 家企业招聘官网，并允许用户添加其他企业官网。
- 使用通用 HTML 适配器读取公开页面。
- 动态渲染、验证码、登录页和特殊接口需要专用适配器。
- 当前刷新由用户主动触发；软件关闭时不会在后台自动更新。

## 推荐架构

1. **来源目录**：优先登记国家及省级公共就业平台、企业招聘官网和事业单位公开招聘平台。每条来源记录主办方、地区、招聘类型、适配器、最近成功时间和使用限制。
2. **来源适配器**：每个平台单独处理分页、地区字段、发布日期和详情页；不绕过登录、验证码、访问控制或反爬机制。
3. **标准化岗位库**：统一为企业、岗位、城市、招聘类型、JD、发布日期、原始链接、首次发现时间、最后确认时间和内容指纹。
4. **增量刷新**：每天建议 08:00、16:00 更新两次。优先读取有变化的页面，根据内容指纹区分新增与更新；连续多次未发现后再标记“疑似关闭”，不立即删除。
5. **城市快照**：客户端按城市下载或读取最近快照。用户点击刷新时，仅刷新所选城市相关来源，并显示刷新时间、成功来源数、失败来源数和新增岗位数。
6. **人工核验**：所有结果保留原始官方链接，投递前由用户确认岗位仍开放并本人完成投递。

## 本地版与云端的边界

纯本地模式可以在用户打开软件或点击刷新时扫描，但电脑关机时无法按计划更新，也不适合每个用户重复扫描全国来源。

要稳定实现每天两次的全国索引，推荐使用一个只处理公开岗位信息的轻量云端更新服务；简历、AI 密钥、投递记录仍保存在用户本地。客户端只向岗位服务发送城市、岗位名称和招聘类型等筛选条件，不上传简历。

## 来源优先级

1. 国家级公共就业与高校就业平台。
2. 人社部门公布的省级公共就业和人才招聘平台。
3. 企业官方招聘网站。
4. 事业单位及国有企业官方公开招聘公告。

第三方招聘平台只有在获得明确授权或使用其正式开放接口时才接入。

## 上线前验收

- 界面始终显示覆盖来源数和最近更新时间。
- 随机抽查岗位必须能回到原始官方页面。
- 不把抓取失败误判为岗位关闭。
- 不宣称“全国全部岗位”或“实时全量”。
- 记录各来源的失败率、重复率和过期率。
